# PyTorch 2.6 weights_only=True Checkpoint Loading Bug

Link back to: [[notes/context/overview.md|Project Overview]]

## Problem Description
When attempting to resume Hugging Face Transformers model training from a local checkpoint under PyTorch 2.6+, the process crashed with a `RuntimeError: Cannot use weights_only=True with files saved in the legacy .tar format.` during loading of the optimizer state dictionary file (`optimizer.pt`).

## Root Cause
In PyTorch 2.6, the default behavior of `torch.load` was changed from `weights_only=False` to `weights_only=True` for security reasons. However, the optimizer state files generated by Hugging Face's trainer use legacy storage configurations. When `transformers` tries to load the checkpoint, PyTorch's default setting blocks extraction of internal storage directories, throwing a tarfile `KeyError`.

## Solution & Monkeypatch
A global monkeypatch was added to the training pipeline right after importing PyTorch to intercept calls to `torch.load` and force `weights_only=False` when it is requested:

```python
import torch
original_load = torch.load
def patched_load(*args, **kwargs):
    if "weights_only" in kwargs:
        kwargs["weights_only"] = False
    return original_load(*args, **kwargs)
torch.load = patched_load
```
This forces all state loading functions to evaluate legacy checkpoints successfully.
